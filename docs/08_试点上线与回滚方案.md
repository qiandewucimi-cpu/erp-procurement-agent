# 08 试点上线与回滚方案

## 目标

将本项目从离线作品推进到客户测试环境验证，先证明数据映射、权限和业务价值，不直接进入生产写入。

## 分阶段试点

1. **离线回放**：使用脱敏或合成样本，只读运行解析、检索、校验和草稿生成。
2. **客户沙箱只读**：HTTP Adapter 查询物料与订单，不开放写接口；完成契约、鉴权、分页、限流验证。
3. **影子模式**：生成预览但不提交，与人工结果比对金额、阻断项和处理时间。
4. **受控写入**：小范围 operator/approver，强制职责分离，设单量/金额阈值和人工复核。
5. **扩大范围**：仅在指标、审计和回滚演练均达标后逐步放量。

## 建议试点指标

- 草稿字段与金额一致率、异常检出率、人工修正率。
- 单据处理时长与人工步骤减少量。
- 越权写入数、重复单据数、未审计状态变更数必须为 0。
- LLM、工具与 ERP Adapter 的成功率和 P95 延迟。

具体阈值需与客户业务负责人共同确认，本项目不虚构生产 SLA。

## 停止与回滚条件

出现权限绕过、重复写入、金额不一致、敏感数据泄露、持续 ERP 故障或审计链缺失时立即停止写入：

1. 关闭 Agent 写权限或切回只读/影子模式。
2. 保留 request_id/action_id/审计证据，停止自动重试。
3. 对已提交的 Demo 单据通过受控 `rollback` 状态迁移处理；真实 ERP 按客户撤销流程执行，不假设通用回滚 API。
4. 恢复上一个已验收版本与配置，验证健康、权限、幂等和核心用例。
5. 完成根因分析、安全复核和回归后再决定是否恢复试点。

## 变更控制

每次试点发布关联 Git 提交、配置版本、评测报告和批准人；密钥不进入 Git。公开镜像与客户部署配置分离。
