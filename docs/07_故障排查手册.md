# 07 故障排查手册

## 通用路径

先检查 `/health`，保存 `X-Request-ID`，再按该标识查 JSON 日志，最后用 `/metrics` 判断失败集中在哪一层。详细字段见 `可观测性与排障.md`。

| 现象 | 优先检查 | 处理 |
|---|---|---|
| 页面打不开 | 8000/8501 端口、启动器最后输出 | 单独启动 API/UI，确认本机端口未占用 |
| `/agent/chat` 提示模型不可用 | `llm_enabled`、模型地址、网络 | 校验 `.env`，用 `/agent/prepare` 验证确定性链路 |
| 401/403 | `auth_enabled`、Token 角色 | 使用入口绑定的合法身份，不在请求体伪造 operator |
| 409 | action 状态、确认口令、自审 | 查 `/approvals` 与 `/audit`，按状态机完成审批 |
| BOM 全部未建档 | 是否先导入对应合成物料档案 | 使用模板导入；检查编码列与允许文件类型 |
| ERP 502/503 | `erp_http.request` 日志、客户测试 API | 检查地址/Token/超时/限流；不要无限重试 |
| 重复单据疑虑 | action_id、审计、订单唯一号 | 使用同一 action 重试；不要新建多个预览替代重试 |
| 指标为空 | 进程是否刚重启、是否产生请求 | 指标为进程内存，先执行一次请求 |

## 升级信息清单

提交问题时只提供时间、`request_id`、`action_id`、接口、状态码、错误类型和脱敏日志。不要提供 API Key、Bearer Token、完整 BOM、价格或对话正文。
