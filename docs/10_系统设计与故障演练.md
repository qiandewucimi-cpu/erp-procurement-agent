# 10 系统设计与故障演练

## 白板题：把当前 Demo 推进客户测试环境

### 先问清楚

1. 日单量、并发峰值、允许延迟和可接受失败方式是什么？
2. ERP 提供同步 API、异步任务还是批量导入？是否支持幂等键和事务？
3. 用户身份来自 SSO/OAuth 还是内部网关？谁能发起、审批、撤销？
4. 哪些字段和规则由 ERP、合同系统、BOM 或人工负责？
5. 数据分级、日志保留、审计和跨境要求是什么？

### 目标架构

```text
企业入口/SSO
   -> API Gateway（鉴权、限流、request_id）
   -> Agent Orchestrator（会话与工具规划）
   -> Policy/Approval Service（RBAC、职责分离、状态机）
   -> ERP Adapter（契约映射、幂等、重试）
   -> 客户 ERP 沙箱

知识文档 -> 检索服务 -> 引用与拒答门禁
全链路 -> OpenTelemetry -> 日志/指标/告警
任务状态 -> 外部数据库；耗时任务 -> 队列/Worker
```

### 关键取舍

- 同步与异步：查询和预览可同步；批量建单进入队列，返回 job_id，避免 HTTP 超时导致重复提交。
- 至少一次与幂等：消息允许重试，但写操作必须以业务幂等键去重；不能只依赖进程内锁。
- 模型与策略：模型输出永远视为建议；权限、金额、字段和状态迁移由策略服务与业务代码判定。
- RAG：检索结果携带文档版本、来源和分数；低于阈值拒答；规则发布触发回归评测。
- 数据：敏感正文不进入普通日志；密钥进入托管服务；上传文件做病毒、类型和内容扫描。

## 故障演练

| 场景 | 观察信号 | 立即动作 | 根因与修复 | 恢复门禁 |
|---|---|---|---|---|
| LLM 超时/5xx | `llm.request` 失败率和 P95 上升 | 停止自动编排，保留只读/确定性入口 | 检查供应商、网络、限流；有界重试与熔断 | 模型冒烟 + 40 条评测 |
| ERP 401/403 | Adapter 稳定鉴权错误 | 禁止重试写入，通知凭证负责人 | 校验密钥版本、权限范围和时钟 | 沙箱只读 + 最小写入契约测试 |
| ERP 409/重复单 | 幂等冲突、相同 action_id | 查询原操作结果，不新建 | 对齐幂等键生命周期和事务边界 | 并发/重复提交回归 |
| RAG 返回伪引用 | 拒答率下降、低分结果增多 | 提高阈值或回滚知识版本 | 补负例、检查切块/别名/embedding | RAG 门禁全部通过 |
| 错误规则发布 | 阻断率或人工驳回率突增 | 回滚规则版本，冻结写入 | 业务 owner 复核差异 | 规则 diff + 回归 + 批准人 |
| 队列积压 | job age、depth 上升 | 限流新任务，扩 Worker | 下游变慢、毒消息或容量不足 | 队列恢复且失败任务重放验证 |
| 审计链缺失 | action 无完整事件序列 | 停止受控写入 | 追踪上下文/日志出口故障 | 审计完整性检查 |

## 容量估算答题模板

先用客户数据估算，不虚构 SLA。例如日均 10,000 张 BOM、峰值 10 倍、每张 20 行：先计算峰值请求和 ERP 调用放大倍数，再决定连接池、队列分区和限流。模型 token 成本按真实 prompt/response 采样；缓存只用于只读规则和物料查询，绝不缓存授权决策或复用写入结果。

## 灰度与回滚

1. 只读：验证身份、字段映射、查询正确率。
2. 影子：生成草稿但不写 ERP，对比人工结果。
3. 小范围写入：限定用户、供应商和金额，双人审批。
4. 扩大范围：根据错误率、人工修改率、延迟和审计完整率逐步放量。
5. 任一停止条件触发：关闭写开关、保留只读、回滚版本并核对已提交单据。

## 面试时主动承认的边界

当前仓库没有真实 SSO、消息队列、分布式锁、集中日志或客户 ERP 合约；以上是迁移设计，不是已实现功能。已有实现证明的是接口隔离、安全状态机、故障映射和评测方法。
