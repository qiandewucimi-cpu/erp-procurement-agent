# 面试演示：5 分钟脚本

## 演示前 30 秒自检

运行 `python smoke_interview.py`。脚本使用临时 SQLite 数据库且不调用外部模型，应显示 7/7 通过；它验证正常金额、异常阻断、viewer 越权、审批提交、重复幂等和工具指标。随后再启动 UI，避免把环境问题带进正式演示。

## 0:00–0:40 问题与定位

“这是一个外贸采购 ERP 安全操作 Agent。它用合成数据复现 BOM 到采购 PO：模型负责理解意图和编排工具，但金额、校验、权限和写入由确定性代码控制。我没有把 Demo 描述成真实生产 ERP 接入。”

展示 README 架构图，指出 8 个工具、ERP Adapter 与审批状态机。

## 0:40–1:50 正常草稿

先展示页面顶部的模型状态。无模型配置时请说“确定性离线回退调用工具”，不要把它讲成模型自主编排。默认鉴权关闭的UI演示，与开启RBAC的 `smoke_interview.py` 分开验证。

输入：`根据 正常示例_BOM.xlsx 生成采购 PO 草稿，先不要写入。`

展开工具轨迹，工具解析3行物料并计算 ¥24164；此时只有 action_id 和变更预览，正式订单未写入。只有页面明确显示模型启用时，才演示并说明模型选择工具。

## 1:50–2:40 异常阻断

输入：`检测 异常示例_BOM.xlsx 的物料错误。`

指出未建档与非法数量是 blocking，名称差异是 warning。强调业务校验来自确定性规则，不由模型自由判断。

## 2:40–3:40 安全写入

默认关闭鉴权的UI展示草稿与精确确认。开启RBAC后还需operator发起、独立approver审批，禁止自审。UI只有固定身份令牌输入，不能用默认单身份会话声称完成了职责分离验收；该项运行 `smoke_interview.py` 展示。确认使用当前会话工具真实返回的action_id和完整口令“确认提交”，随后查看订单与审计。

补一句：“四路并发确认的评测只生成一个 PO，后到请求得到同一结果，而不是重复建单。”

## 3:40–4:25 集成与排障

展示 `ERPAdapter`：SQLite 保证离线演示，HTTP Adapter 展示客户测试 API 对接所需的 Bearer 鉴权、超时、有限重试、稳定错误映射和幂等键。

调用 `/metrics` 或展示 JSON 日志，指出 request/session/action/tool 的关联，以及日志不记录提示词、载荷或密钥。

## 4:25–5:00 证据与边界

展示[验证索引](验证索引.md)：2026-10-21本地运行101项单测、25条离线场景和7项业务冒烟通过。`evals/REPORT.md` 的40/40来自2026-09-13的25条确定性+15条模型场景；98项单测与89%覆盖率也属于历史记录，本次没有重新调用模型或测量本地覆盖率。MCP暴露8个工具。

RAG检索证据可运行 `python evals/run_rag_eval.py` 查看。2026-10-21仓库合成语料的Recall@3为100%、MRR为0.883、拒答命中率为100%，不代表所有问题都正确。演示自然语言知识问答前确认模型已启用，并在轨迹核对真实检索调用；离线聊天回退不证明模型问答能力，也不保证任意问题均不会补写无依据内容。

收尾：“如果进入客户项目，我会先做沙箱只读和影子模式，通过字段一致率、异常检出率、处理时长与零越权指标验收，再小范围开放受控写入。”

## 面试追问准备

- 为什么不是工作流？模型会自主选择工具和顺序；高风险决策则刻意确定性化。
- 为什么需要审批加确认？审批解决职责分离，确认解决当前操作意图，两者不是同一控制。
- 为什么不用真实数据？公开作品的目标是证明架构与工程方法，真实业务数据不能越界。
- 还有哪些生产差距？SSO/IAM、集中日志与告警、分布式幂等、密钥托管、上传安全、备份恢复和真实契约测试。
